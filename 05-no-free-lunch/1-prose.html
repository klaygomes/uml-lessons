The universal filter

Theo from the platform team has been reading your design notes, and he is not impressed. “All this care about hypothesis classes,” he says, scrolling past lesson 1’s one-feature hypotheses and lesson 3’s agnostic guarantees. “You keep choosing what the learner is allowed to believe. Why decide in advance? I’ve built a filter with no bias at all. It considers every hypothesis there is, every possible way of labelling every possible message. It never rules anything out, so it can never be wrong about what junk looks like. Give it enough labelled mail and it will learn any junk rule the spammers come up with, including ones none of us has imagined.”

He wants to replace the course’s careful classes with his universal filter, and the pitch is attractive. Every class you have chosen so far was a bet, and lesson 1 showed you what happens when the bet is wrong: the rat, whose bias blinds it to a world where a sound causes sickness. Theo’s filter makes no bet, so it can never lose one.

You have a nagging feeling that lesson 1 already answered him. It proved that when a learner considers every hypothesis, the examples leave every unseen message perfectly balanced: exactly half of the consistent hypotheses, those that agree with every example, call it junk. But read lesson 1 again and you will find that it stopped short. It said that a learner with no bias has nothing to go on, and it also admitted that a learner whose tie-breaker happens to match the truth would get lucky. Theo is not claiming his filter is lucky. He is claiming that some clever tie-breaker, some rule for labelling unseen messages, works well on every task. Maybe there is one, and we just haven’t found it.

So here is the question this lesson settles. Is there a universal learner: one learner, and one number of examples mmm, such that on every learning task, given mmm examples, it probably returns a hypothesis with small true risk? If there is, Theo wins and the course can stop worrying about bias. If there isn’t, we owe him a proof, and we owe ourselves an account of what a bias costs and what it buys.

Where we stand

The proof leans on every tool we already own, so here they are again, each formula read once more.

Since lesson 3 a learning task is the way labelled mail arrives: some messages come often, some rarely, and each comes with its label. A duel on four messages

Let’s shrink the mail room until we can check everything by hand. Keep only two features, F (the subject says “FREE”) and L (the message has a link), so there are four possible messages: 00, 01, 10 and 11. Each training message is drawn uniformly from these four, and we draw m=2m = 2m=2 of them.

Now set up a duel. Theo picks a learner. You pick the target, the labelling function fff that decides which of the four messages are junk. Then the training sequence is drawn, his learner returns a hypothesis, and we score its true risk. You are allowed to know his learner before you pick, which is the whole point: you are looking for a task on which it fails.

Theo’s first learner is lesson 1’s memorizer: it returns the label of every message it has seen, and says keep for every message it hasn’t. Which target would you pick against it? Think about it before you read on.

The memorizer’s weakness is its default. It says keep for every unseen message, so pick the target that labels every message junk. Then the memorizer is right on what it has seen and wrong on everything else, and its true risk is simply the fraction of the four messages it hasn’t seen. There are 4×4=164 \times 4 = 164×4=16 equally likely training sequences, and they come in two kinds.

The function expected_risk in the snippet a little further down computes exactly this average.

Theo shrugs and patches it. His second learner fills in unseen messages by majority: if most of the labels it has seen are junk, it says junk for the unseen ones, and otherwise keep. Against “everything is junk” it is now perfect, since it sees two junk labels and copies them everywhere. So you change targets. Try “junk exactly when the subject says FREE”: 00 and 01 are keep, 10 and 11 are junk. Now whenever both training messages share a label, majority copies that label onto the unseen messages of the other kind, and gets them wrong. The bookkeeping is a little longer, so let Python do it. import itertools

C = ["00", "01", "10", "11"]
targets = list(itertools.product([0, 1], repeat=4))
sequences = list(itertools.product(C, repeat=2))

def memorizer(S):
    return lambda x: dict(S).get(x, 0)

def majority(S):
    vote = int(2 * sum(y for _, y in S) > len(S))
    return lambda x: dict(S).get(x, vote)

def expected_risk(A, f):
    g = dict(zip(C, f))
    return sum(A([(x, g[x]) for x in xs])(c) != g[c]
               for xs in sequences for c in C) / (16 * 4)

for A in (memorizer, majority):
    r = {f: expected_risk(A, f) for f in targets}
    worst = max(r, key=r.get)
    print(sum(r.values()) / 16, r[worst], worst)

Why every learner has the same average

They tie. Every rule averages 0.2931 over the 256 targets, and every rule has a target that pushes it well above a quarter. Here is why, and you have seen the trick before.

Fix one training sequence, say it contains the messages 000, 011 and 101 (one of them twice), and fix one message it doesn’t contain, say 110. Now take any target fff and its twin: the target that agrees with fff everywhere except at 110, where its label is flipped. On the training sequence, the twins are indistinguishable. They give the same labels to 000, 011 and 101, so the learner receives exactly the same examples under both, and so it returns exactly the same hypothesis. That hypothesis says one thing about 110, either junk or keep. One twin says junk there and the other says keep, so exactly one of the twins catches the learner out.

[diagram:pairing: built on the lesson page]

That is lesson 1’s flip map, the one that paired consistent hypotheses by flipping one unseen label, now applied to targets instead of hypotheses. Every target has exactly one twin at 110, so the 256 targets split into 128 twin pairs, and in every pair the learner is wrong at 110 exactly once. Averaged over all targets, the learner is wrong at 110 exactly half the time. And nothing in that argument cared what the learner does. Keep, junk, majority, nearest, a neural network, a crystal ball: as long as it is a function of the examples it sees, the twins defeat it at every unseen message half the time.

So, averaged over all targets, the expected true risk of any learner that gets its seen messages right is half the expected fraction of messages it hasn’t seen. (A learner that also errs on seen messages only does worse.) That fraction depends on how many distinct messages turn up in the training sequence, and not on the learner at all, which is why every rule in the lab got the same number.

Two more facts finish the argument, and they are the heart of this lesson.

First, if the training sequence has mmm messages and the domain has 2m2m2m, then at most mmm distinct messages can appear, so at least half are unseen. Half of “at least half” is at least a quarter. Averaged over all targets, every learner’s expected true risk is at least 1/41/41/4.

Second, the maximum is at least the average. If the average over targets is at least 1/41/41/4, then some single target has expected risk at least 1/41/41/4, since not every number in a list can be below the list’s average. That target is a task on which the learner fails.

This is the No-Free-Lunch theorem, which lesson 1 promised. Let’s state it properly and prove it properly.

The formal statements

Setting. Binary classification with the 0-1 loss over a domain X\mathcal XX, with tasks D\mathcal DD and true risk LDL_{\mathcal D}LD​ as in the recap. A learner AAA is a deterministic algorithm: it maps each training sequence SSS to a hypothesis A(S):X→{0,1}A(S): \mathcal X \to \{0, 1\}A(S):X→{0,1}, so the same SSS always gives the same hypothesis. Before the statement, here is what it says in words. The averaging argument found, for every learner, a target that pushes its expected true risk to at least a quarter. An expectation is a statement about all training sequences at once, and you only ever get one. So the theorem trades the quarter for a pair of numbers about the one sequence you get: with a chance of at least one in seven, the learner is wrong on at least an eighth of the mail. Theo’s filter, on an infinite domain

Theo’s filter does not work on four messages, or eight, or 256. It works on real messages, and a real message is text of any length. That is the answer to Theo. There is no “enough labelled mail”. Whatever number of labels he names, the domain has more than twice that many messages, and there is a junk rule, one that some hypothesis labels perfectly, on which his filter has a one-in-seven chance or more of being wrong on at least an eighth of all messages.

How do we escape? By doing exactly what the course has been doing: using prior knowledge about the task to rule out the distributions that would defeat us, and writing that knowledge down as a restricted hypothesis class. Which raises the real question. If the class of all functions is too rich, how rich should a class be? On one side, we want the class to contain the truth, or at least something with small true risk. On the other, we have just seen that we cannot take the richest class there is. Lesson 1 named the two ways to get this wrong: the rat’s, a bias that rules out the truth, and the pigeon’s, a bias so weak that a coincidence passes for a rule. Now we can measure them.

Two ways to be wrong

Start with a small case. Back in the four-message world, let the truth be “junk when FREE or a link”, so only 00 is keep. Let the class hold three hypotheses: always keep, “junk exactly when FREE”, and “junk exactly when a link without FREE”, which calls only 01 junk. The best of the three is “junk exactly when FREE”, wrong only on 01, a quarter of the mail. Now two examples arrive, (01, junk) and (00, keep). The third hypothesis gets both right and the other two get one wrong each, so ERM picks the third, and it is wrong on 10 and 11, half the mail. That half splits into a quarter that no member of the class could have avoided, and a quarter that came from trusting two examples.

The bias-complexity tradeoff

Put it together and you have the bias-complexity tradeoff. Choose a very rich class and the approximation error shrinks, but the estimation error may grow, because a rich class has room for a coincidence to beat the truth: that is overfitting, the pigeon’s failure. Choose a very small class and the estimation error shrinks, but the approximation error may grow, because the truth, or anything close to it, may not be in the class: that is underfitting, the rat’s failure. The best class sits between them, and where it sits depends on how many examples you have. In our eight-feature world, recomputing the table for other budgets, the best rung climbs with the budget:

Is there a perfect class? Yes, in principle: the class containing only the Bayes optimal predictor from lesson 3, the rule that gives each message its more likely label. Its approximation error is the Bayes risk, the best possible, and its estimation error is zero, since there is nothing to choose. But building it requires knowing D\mathcal DD, and if we knew D\mathcal DD we wouldn’t need to learn. Learning theory asks how rich a class can be while the estimation error stays reasonable. Practice spends much of its effort designing classes whose approximation error is small for the domain at hand. The point of prior knowledge is to land somewhere that both errors are tolerable: you don’t know the junk rule, but you know enough about junk to guess which features carry it.

One honest caveat about the lab you are about to use. It shows you the approximation error because it knows the truth. In the real mail room you don’t, and picking the rung from data alone is a problem of its own: lesson 7 handles it by spreading confidence across the ladder, and lesson 11 by holding out examples to validate.

The algorithms

Two algorithms carry this lesson. The first is the table learner, ERM over Hk\mathcal H_kHk​. The second is the adversary from the proof, written as code: given a learner, it finds the task that defeats it.

TableERM(S, k):
  votes ← empty hash map from cells to (junk count, total)
  for i = 1..m:
    c ← first k features of x_i
    votes[c].junk += y_i;  votes[c].total += 1
  table ← for each cell c in votes: 1 if 2·junk > total else 0
  return h(x) = table[first k features of x] if present, else 0

Adversary(A, C, m):
  best ← none
  for each target f: C → {0, 1}:
    total ← 0
    for each sequence (x_1, ..., x_m) in C^m:
      h ← A(((x_1, f(x_1)), ..., (x_m, f(x_m))))
      total += (number of c in C with h(c) ≠ f(c)) / |C|
    if total / |C|^m > risk of best: best ← (f, total / |C|^m)
  return best

What people get wrong

“No free lunch means learning is impossible.” It means learning is impossible without prior knowledge. Every task the theorem builds is solved easily by a learner that expected it. The theorem is an argument for choosing a class, not against learning.

“So every learner is equally good.” Only on average over all targets, each counted equally. The real mail room is not a uniformly random labelling of all messages: junk has structure, and a class that matches that structure beats Theo’s filter by a factor of four at 50 labels. Prior knowledge is exactly the claim that your task is not a uniformly random target.

“A bigger class is safer, because it is more likely to contain the truth.” It is more likely to contain the truth, which lowers the approximation error. But it also contains more impostors, which raises the estimation error. In the ladder at 50 labels, the class that contains the truth loses to every rung but the constant hypotheses.

“The approximation error is bad luck with the data.” No. It is a property of the class and the task, fixed before any example arrives. More examples shrink the estimation error and leave the approximation error exactly where it was, which is why the rat in a world of clicks never recovers.
