Smeared words

Lesson 23a ended with a fast filter and a quiet week. Then the compliance desk wrote in. A customer is disputing a quarantined message, and the desk has to show exactly which watchlist words it contained, and how often. The desk has nothing to go on but what the archive keeps: the squeezed numbers.

Let’s rebuild their problem on a small scale. The watchlist has six words, “free”, “prize”, “winner”, “urgent”, “claim” and “wire”, and every quarantined message uses one of them some number of times. The desk squeezes each message to three numbers, y=Wxy = Wxy=Wx, where WWW is a compression matrix: a table with three rows and six columns, so that yyy holds three weighted sums of the six counts. (A message with six counts is a vector x∈R6x \in \mathbb R^6x∈R6, and R3,6\mathbb R^{3,6}R3,6 is the set of tables with three rows and six columns.) The columns of WWW are six unit-length directions from the centre of an icosahedron, the twenty-sided solid, to six of its corners, one from each opposite pair. They are as spread apart as six directions in three dimensions can be, and the next sections look at this matrix properly.

The desk engineer’s decoder is the one lesson 23a would suggest: among all messages that squeeze to the stored yyy, return the shortest. For this WWW the shortest is x~=12W⊤y\tilde x = \tfrac12 W^\top yx~=21​W⊤y. The W⊤W^\topW⊤ is the transpose of WWW, the same table turned on its side so that rows become columns, and the 12\tfrac1221​ is there because each of the three rows of WWW has squared length 2. The recovered message is x~\tilde xx~, as before. Take a message that says “urgent” two and a half times and nothing else.

You might hope for a better recovery matrix. There is none, and the reason is the null space of lesson 23a. Suppose some matrix UUU recovered every one-word message exactly, so that UWx=xUWx = xUWx=x whenever xxx has a single nonzero count. The one-word messages include the six messages e1,…,e6e_1, \dots, e_6e1​,…,e6​, each with a single count of 1, and every message is a sum of multiples of those. In one sentence: a recovery matrix that is right on every one-word message would be right on every message, and the null space forbids that, so the decoder cannot be a matrix.

Yet the desk’s messages are not arbitrary vectors. They use one word out of six, and in the real mail a message uses about 60 of 50,000. A decoder that uses that fact can be something other than a matrix, and that is the idea of this lesson. Three questions come one after another. Is a message that uses few words determined by its squeezed numbers at all? Can it be found without trying every possible set of words? And which squeezes make both true, and how can you be sure, rather than hope? The answers are called compressed sensing.

Sparse messages

The desk’s smear came from the null space: with n<dn < dn<d, no recovery matrix can undo a squeeze. Yet look at an actual message. Out of 50,000 word counts, a typical message has maybe 60 that are not zero. Writing down 50,000 numbers to record 60 of them is absurd.

The count of nonzero entries has a name. For x∈Rdx \in \mathbb R^dx∈Rd,

∥x∥0=∣{ i:xi≠0 }∣.\|x\|_0 = \big|\{\, i : x_i \neq 0 \,\}\big| .∥x∥0​=​{i:xi​=0}​.
  • { i:xi≠0 }\{\, i : x_i \ne 0\,\}{i:xi​=0} is the set of positions iii such that entry iii is not zero: the words the message actually uses.
  • ∣⋅∣|\cdot|∣⋅∣ counts how many positions that set contains.
  • The subscript 0 is a convention: ∥x∥0\|x\|_0∥x∥0​ is not a true length (doubling xxx does not double it), but it sits naturally next to ∥x∥1\|x\|_1∥x∥1​ and ∥x∥2\|x\|_2∥x∥2​, which we meet in a moment.

In one sentence: ∥x∥0\|x\|_0∥x∥0​ is the number of distinct words in the message. A message is s-sparse when ∥x∥0≤s\|x\|_0 \le s∥x∥0​≤s. The message “free free free prize winner winner” has counts 3, 1 and 2 on three words and 0 on the other 49,997:

It prints 3 49997: ∥x∥0=3\|x\|_0 = 3∥x∥0​=3, so this message is 3-sparse, and so is any message using at most three words.

An s-sparse message can obviously be stored without loss as sss pairs (word index, count). So why not do that? Because that representation is not a fixed linear squeeze: you have to see the whole message first to know which positions to keep. Compressed sensing asks for something stranger. Fix one matrix WWW with nnn rows, the same for every message, chosen before any message exists. Store y=Wxy = Wxy=Wx. Then recover every s-sparse xxx exactly. A linear squeeze can be computed on the fly: as the parser reads each word, it adds that word’s column of WWW to a running total of nnn numbers, and the 50,000-count vector is never built. This is also why the idea matters outside the mail room: a camera or a medical scanner can measure the nnn weighted sums directly, instead of measuring everything and throwing most of it away. The same works for a message that is sparse after a fixed change of basis, x=Uαx = U\alphax=Uα with UUU orthonormal and α\alphaα sparse, since Wx=(WU)αWx = (WU)\alphaWx=(WU)α.

How can that work, when we proved that every squeeze has a null space? Because exact recovery of every message was impossible, but we only ask for sparse ones. The null space contains no sparse vectors, if WWW is chosen well, and the decoder that finds the sparse message is not a matrix, as the desk learned, but it can exist. Three results make this precise:

  1. If WWW has a property called the restricted isometry property, every sparse message can be recovered exactly from WxWxWx.
  2. The recovery can be computed in polynomial time, by a linear program.
  3. A random WWW has the property, with high probability, once nnn is of order sln⁡ds \ln dslnd.

The restricted isometry property

The idea first. A random projection keeps the lengths of a finite set of vectors. Compressed sensing needs more: it needs WWW to keep the length of every sparse vector, infinitely many of them. If it does, then no sparse vector is squeezed to zero, and that is exactly what recovery needs.

Definition (restricted isometry property). A matrix W∈Rn,dW \in \mathbb R^{n,d}W∈Rn,d is (ε,s)(\varepsilon, s)(ε,s)-RIP if for every x≠0x \neq 0x=0 with ∥x∥0≤s\|x\|_0 \le s∥x∥0​≤s,

∣∥Wx∥2∥x∥2−1∣≤ε.\left| \frac{\|Wx\|^2}{\|x\|^2} - 1 \right| \le \varepsilon .​∥x∥2∥Wx∥2​−1​≤ε.
  • “x≠0x \ne 0x=0 with ∥x∥0≤s\|x\|_0 \le s∥x∥0​≤s” is every nonzero s-sparse vector.
  • The fraction is the squared distortion of xxx, exactly as in the Johnson-Lindenstrauss lemma.
  • An isometry keeps all lengths; “restricted” means we only ask for it on sparse vectors, and only up to a fraction ε\varepsilonε.

In one sentence: WWW is (ε,s)(\varepsilon, s)(ε,s)-RIP when it gets the squared length of every s-sparse vector right within a fraction ε\varepsilonε. The smallest such ε\varepsilonε for a given WWW and sss is its RIP constant.

Recovery by a linear program

Here is the surprising part. Replace the count of nonzero entries by the sum of absolute values,

Random matrices have the property

The last piece: where do RIP matrices come from? Checking the RIP of a given matrix means checking every set of 2s2s2s columns, which is the same impossible search as before. So we do not check. We draw WWW at random and prove that it is RIP with high probability.

The idea in words. The Johnson-Lindenstrauss lemma handles a finite set of vectors. The sparse vectors on one fixed set III of sss words form a whole subspace, infinitely many vectors. But it is enough to control a finite net of them, a set of unit vectors so dense that every unit vector of the subspace is close to one of them, and then bootstrap from the net to everything. Finally, take a union bound over all (ds)\binom{d}{s}(sd​) choices of III.

PCA or compressed sensing?

You now have two ways to squeeze with a promise of recovery, PCA from lesson 23a and compressed sensing from this lesson, and they rest on different assumptions about the messages.

PCA assumes the messages lie near a low-dimensional subspace. It recovers perfectly whenever the archive lies exactly in an nnn-dimensional subspace, and it is the best linear squeeze with linear recovery for the archive you fit it on.

Compressed sensing assumes the messages are sparse, in some known basis. It recovers perfectly every s-sparse message, from about sln⁡ds \ln dslnd numbers, with a nonlinear decoder.

Each wins where the other’s assumption fails. The single-word messages e1,…,ede_1, \dots, e_de1​,…,ed​ are 1-sparse, so compressed sensing recovers them all from order ln⁡d\ln dlnd numbers, where PCA loses most of each one. In the other direction, take mmm messages that lie exactly in an nnn-dimensional subspace. PCA recovers them perfectly with nnn numbers. They are also nnn-sparse in any orthonormal basis whose first nnn vectors span the subspace, so compressed sensing works too, but it needs on the order of nln⁡dn \ln dnlnd numbers, and with exactly nnn it can fail. For the mail room, word counts are sparse and do not lie near a small subspace, so compressed sensing’s assumption is the right one for recovering messages, and a random projection is the right tool for keeping distances. If all you need is the best summary of a fixed archive, for instance to plot it or to find its main themes, PCA is the right one.

What people get wrong

“A better recovery matrix would fix the smear.” No matrix can. One that was right on every one-word message would be right on every message, because messages are sums of one-word messages and a matrix respects sums, and the null space forbids that. The decoder has to be nonlinear, and exploiting sparsity is what makes it so.

“Exact recovery of a squeezed message is impossible.” It is impossible for every message, because of the null space. It is possible for every sparse message, when the null space contains no sparse vectors, which is what the RIP for 2s2s2s guarantees.

“If the linear program recovered my test messages, the matrix is fine.” Success on the messages you tried is not a guarantee for the next one. In the build-it challenge the linear program recovers a two-word message from three numbers, yet some two-word messages are indistinguishable from each other at that size, so no decoder can recover them all.

“The constants in the RIP theorem tell you how many measurements you need.” They give a number that certainly suffices, from a crude proof; the sln⁡ds \ln dslnd shape is the lesson, the 216 is not.
