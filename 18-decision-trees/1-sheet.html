Decision Trees

Overview

Objective: after this, you can define a decision tree over yes/no features and read its paths as rules; prove that threshold trees with kkk leaves shatter kkk points (so unrestricted trees are not PAC learnable) and state why trees over {0,1}d\{0,1\}^d{0,1}d have VC dimension 2d2^d2d; build the prefix-free preorder code with (n+1)⌈log⁡2(d+3)⌉(n+1)\lceil\log_2(d+3)\rceil(n+1)⌈log2​(d+3)⌉ bits, prove it prefix-free, and derive the description-length bound for trees from lesson 7b's MDL bound; run ID3 with training-error, information-gain and Gini gains, state its cost, and prove that the smooth gains are concave upper bounds of the training error that never go blind the way training error does; prune a tree bottom-up with the bound; reduce real-valued threshold splits to yes/no features (with proof) and find the best threshold in O(dmlog⁡m)O(dm\log m)O(dmlogm); define a random forest and say what it costs in time and in readability.

Misconception: "ID3 finds the best tree." Why wrong: it is greedy; minimizing the bound is NP-hard (if P ≠ NP), and Problem 2 shows depth-2 ID3 stuck at training error 1/4 where a depth-2 tree has 0.

Second misconception: "zero empirical risk means a good tree." Why wrong: on noisy mail, full ID3 trees memorize the noise: true risk about 0.22 against a floor of 0.1, bound near 0.9.

Third misconception: "pruning with the bound uses the data twice, so the certificate is void." Why wrong: the bound holds for every tree simultaneously and the code is fixed before SSS; only a data-dependent code would void it.

Fourth misconception: "training error is the natural gain." Why wrong: its gain is exactly 0 for every split that leaves both majorities on the same side; about half of random splits (49,934 of 100,000).

Derivation (all proofs are in the prose):

  • Threshold trees with kkk leaves shatter kkk points: chain tree with midpoints (p. 251 states it; the chain construction is ours). Infinite VC dimension, not PAC learnable (lesson 6a).
  • Trees over {0,1}d\{0,1\}^d{0,1}d express every function, VC dimension 2d2^d2d: stated, proof left to Problem 1 (p. 251 defers it to Exercise 1).
  • Tree code prefix-free: end block appears only last (proper prefixes); open-slot counter for injectivity, by induction (the book says "it is not hard to show", p. 252; proof ours). Functions described by a smallest tree with a fixed tie rule (ours; the book treats trees as hypotheses directly).
  • Description-length bound LD(h)≤LS(h)+((n+1)b+log⁡(2/δ))/(2m)L_{\mathcal D}(h) \le L_S(h) + \sqrt{((n+1)b + \log(2/\delta))/(2m)}LD​(h)≤LS​(h)+((n+1)b+log(2/δ))/(2m)​ from Theorem 7.7 (Equation 18.1, p. 252, with log⁡2(d+3)\log_2(d+3)log2​(d+3) unrounded).
  • Gain proposition: upper bounds (Gini by 1−a≥1/21 - a \ge 1/21−a≥1/2; entropy by concavity between H(0)=0H(0) = 0H(0)=0 and H(1/2)=1H(1/2) = 1H(1/2)=1); all gains ≥0\ge 0≥0 by concavity and the law of total probability; strict positivity for entropy and Gini by strict concavity (second derivatives −4-4−4 and −1/(a(1−a)ln⁡2)-1/(a(1-a)\ln 2)−1/(a(1−a)ln2), about −7.7-7.7−7.7 at a=0.75a = 0.75a=0.75; chords reaching the endpoints 0 or 1 handled by Rolle's theorem on φ\varphiφ = CCC minus the chord); training-error gain exactly 0 when p1,p0p_1, p_0p1​,p0​ on the same side of 1/2. The book only states "smooth and concave upper bounds" (p. 254); the proofs and the blindness statement are ours.
  • Threshold reduction: same shape, nodes and training labels (p. 255 says "easy to verify"; proof ours).

Algorithms:

  • ID3 (p. 253): O(md2)O(md^2)O(md2) time (gain by four counts, O(md)O(md)O(md) per level, depth ≤d\le d≤d), O(md)O(md)O(md) space (at most m/2m/2m/2 internal nodes per level), O(d)O(d)O(d) prediction. Ties: argmax toward lowest index, majority toward 1 (our convention; the book leaves ties open). Empty child: leaf 1 vacuously (the book's pseudocode, literally).
  • Generic pruning (p. 254) with the bound as fff: O(n(md+n))O(n(md + n))O(n(md+n)) time; the unchanged tree preferred on ties (ours). Implementation in ref.py: postorder walk, "yes" subtree first.
